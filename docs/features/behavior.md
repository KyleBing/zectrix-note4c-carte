# 固件行为机制

> 说明 **Carte** 运行时怎么工作：上电、按键、**屏幕刷新**、多 App、Web、联网拉数、错误记录。  
> 各 App / Web 配置**做什么**见 [App 功能说明](/features/apps)；总览见 [固件功能说明](/features/)。  
> 本文偏「为什么按下去会这样」。版本：`{{DOC_VERSION}}`

---

## 1. 总体结构

固件是单线程 Arduino `setup` / `loop`，大致分层：

```text
按键 / 电源 / LED          ← app_power / app_led
        │
   main.cpp 路由            ← 切 App / 刷屏（可中断）/ 进 Web / 关机
        │
   ┌────┼────┬────┐
 App 绘制   Web 配置   错误日志
 (todo/…)  (app_web)  (app_errorlog)
        │
   WiFi / Portal / 天气代理
        │
   墨水屏 SSD2683 全刷（可中断）
```

| 模块 | 职责 |
| --- | --- |
| `main.cpp` | App 会话、按键路由、进/出 Web、交互刷屏循环（中断后重刷目标页） |
| `app_power` | DOWN 长按关机、UP/DOWN/BOOT 连击、空闲关机、刷屏中导航装弹 |
| `epd_ssd2683` | framebuffer、全刷波形、BUSY 等待、按键中断停面板 |
| `app_config` | NVS（WiFi、Portal、App 开关、天气位置、定时间隔…） |
| `app_web` | 设备端配置站 |
| `app_*` | 各 App 拉数与画屏 |
| `app_errorlog` | 错误事件环 → LittleFS → Web `/errors` |

## 屏幕刷新机制

### 为什么慢

面板是 **4.2″ 四色（BWRY）**，驱动 **SSD2683**。当前固件只做 **全屏全刷**（写完整帧 + 控制器波形），一次大约 **16 秒**。墨水粒子要多次翻转才能定影，肉眼往往在前几下闪烁时就能认出内容，但控制器仍会跑完整波形。

流程概要：

```text
画进 RAM framebuffer（很快）
  → 上电 / 复位 / 初始化
  → SPI 下发整帧（400×300×2bit）
  → 发 0x12 刷新，轮询 BUSY（主要耗时）
  → 电源关闭 / deep sleep 管脚断电
```

| 场景 | 是否可中断 |
| --- | --- |
| 按键 / 自动刷新触发的 App 全刷 | **可** |
| 开机 splash、配置 Web 说明页 | **否** |
| 定时闹钟醒来「刷一屏再睡」 | **否**（避免半截画面后直接深睡） |

### 可中断刷新（交互）

目标：**不用等约 16 秒才能按下一键**；停手后停在最终想看的那一页，并让该页完整刷完。

1. 全刷开始前：忽略「触发本次刷屏」那次按键的松开，避免误计多一击  
2. BUSY 等待 / 传帧过程中轮询按键；一旦有新的 UP / DOWN / BOOT 意图 → **立刻停波形**（尽力 power-off，不空等 BUSY）  
3. 等松手 + 约 **500ms** 连击窗，合并本次连按次数  
4. 应用到「下一 App / 上一 App / BOOT 页内动作」  
5. **立刻开始目标页的新全刷**；若中途又按键，重复 2–5  
6. 不再按键 → 当前目标页跑完完整波形并停留；成功则 LED **刷完一闪**

连按示例：刷屏中连按 DOWN 三次再停 → 一次前进 3 个已启用 App，只完整刷最终那一页。

中断半截可能短暂残影或发花，属预期；最终页刷完后应正常。下键长按关机在刷新等待里仍然有效。

### LED 与刷屏

刷屏过程中 LED **不**为「刷新进度」闪灯（按键按住仍可亮）。只有**完整成功结束**的那一次全刷才会「刷完一闪」；被中断的那次不会为半截刷新亮完成闪。

## 2. 上电与关机

### 2.1 上电

1. 拉高 `PWR_HOLD` 保持供电  
2. 初始化 LED、电池、NVS、EPD、LittleFS、错误日志、I2C / RTC  
3. 恢复 UI 会话（当前 App、天气模式、相册下标）；若该 App 已关闭 → 落到第一个仍启用的 App  
4. **定时唤醒**：若因 RTC/定时深睡标记醒来且到期 → 刷当前 App（不可中断）→ 再软关机  
5. **交互开机**：**不自动刷屏**（保留上一帧）；新 build 可能先刷 splash  
6. LED **快闪 3 下**表示已开机  
7. 短时间忽略按键抖动  

### 2.2 关机 / 唤醒

| 操作 | 行为 |
| --- | --- |
| 长按 **DOWN ~3s** / 空闲超时 | 见下「两种软关机」 |
| 深睡中按 **DOWN** | 交互开机（不自动刷屏；USB 假关机也能醒） |
| RTC 闹钟（GPIO5） | 定时任务开机：刷当前 App → 再软关机 |
| 空闲超时 | Web **设置**可配；**配置页打开期间不计**；可单独开关「接电是否仍自动关机」 |

#### 两种软关机

关机前按**当前前台 App**决定路径（会话已落盘）：

| 路径 | 何时 | 行为 |
| --- | --- | --- |
| **松电** | 待办；或天气/相册**未开**定时 | 释放 `PWR_HOLD`；近似断电；仅 DOWN 醒；最省电 |
| **定时深睡** | 日历；或天气/相册**已开定时** | **保持** `PWR_HOLD` + deep sleep；PCF8563 闹钟 → INT；RTC 或 DOWN 可醒 |

定时深睡耗电高于松电，但远低于常开。日历约到**次日 0:00**；天气/相册约到 `上次成功刷新 + 间隔`（各有独立开关）。

## 3. 按键模型

| 键 | 角色 |
| --- | --- |
| **UP / DOWN** | 切 App（短按）；UP 长按进 Web；DOWN 长按关机 |
| **BOOT** | **从不切 App**；页内动作，或 Web 里退出配置 |

### 3.1 连击窗口

UP / DOWN / BOOT（非 Web）短按：**松开后静默约 500ms**，窗口内点击合并为一次「跳过 N 步」。刷屏被打断后的连按也走同一套窗口。

### 3.2 配置网页内外

| 场景 | BOOT | UP 短按 | UP 长按 | DOWN |
| --- | --- | --- | --- | --- |
| 普通 App | 页内功能 | 上一个 App | 开 Web | 下一个 App / 长按关机 |
| Web 配置页 | **立刻退出**，刷回当前可用 App | （忽略切换） | AP ↔ 同 WiFi 站点 | （忽略切换） |

Web 里 BOOT **不等** 500ms，松手后尽快 `webStop()` 并刷 App。

### 3.3 各 App 上 BOOT

| App | BOOT |
| --- | --- |
| 待办 | 重新拉 Portal 日记并全刷 |
| 日历 | 重绘（必要时校时） |
| 天气 | **NOW ↔ 7D**，再拉对应接口并全刷；顶栏黄标指示当前档 |
| 相册 | 下一张（可展示列表内） |

天气切模式会先写入会话再联网，避免拉数中途复位后「模式丢了像没按过」。

### 3.4 App 被关掉之后

- 上下键只在**启用**的 App 间循环  
- 只有 **1 个**启用时：**不画**顶栏 App indicator  
- 进 Web 前停在 A，配置里关掉 A，再 BOOT 退出：落到第一个仍启用的 App，**不会**还原到已禁用的 A

## 4. 多 App 与顶栏

启用掩码在 NVS（`apps_enabled`）。顶栏从左到右：标题区 →（可选）App indicator → 电池 / 充电图标。

成功状态一般不再写 `OK` 压在圆点上；失败时短状态字写在 indicator **左侧**。

## 5. Web 配置门户

长按 UP → 优先已存 WiFi 开「同 WiFi 站点」；失败则 AP `Note4C-Carte`（密码 `12345678`）。墨水屏显示模式图标与 URL。

| 路径 | 作用 |
| --- | --- |
| `/` | 状态总览 |
| `/settings` | App 开关、空闲关机、日历/时间 |
| `/help` | 帮助（含 LED；旧 `/led` 跳转至此） |
| `/wifi` | 最多 5 组 WiFi |
| `/auth` | Portal、登录、Diary ID |
| `/todo` | 预览待办正文 |
| `/weather` | 天气开关、城市、定时刷新 |
| `/album` | 编辑 / 抖动 / 上传 / 定时翻页 |
| `/errors` | 错误事件记录 |

保存多为 HTTP 303 + 闪讯；**不会**自动退出 Web。退出靠 **BOOT**（或关机）。

## 6. 联网与各 App 数据

### 6.1 待办

`GET {portal}/diary/detail?diaryId=`，`-` / `=` 解析。失败时屏上「错误详情」并记入错误日志。

### 6.2 日历

读 PCF8563；可联网 NTP。Web 可配周起始、时区、手动写 RTC。

- **醒着**：跨日自动重绘（仅停留在日历 App）  
- **关机**：前台为日历 → 定时深睡约次日 0:00，醒来刷日历再睡  

### 6.3 天气

设备**不存**和风 Key。条件：天气启用 + 已登录 Token + LocationID + Portal Base URL。

- **醒着**：`/weather` 定时开关 + 间隔；到期且停留在天气 App 时拉数刷屏  
- **关机**：前台天气且定时开 → 定时深睡到点拉数刷屏再睡  

经 Portal 代理：

| 模式 | 请求 |
| --- | --- |
| NOW | `/v7/weather/now` + `/v7/air/now` + `/v7/weather/24h`（实况 + 空气 + 前 6 小时柱） |
| 7D | `/v7/weather/7d`（高低气温柱） |

#### NOW 实况区

左侧大天气图标；右侧文案相对图标高度纵向居中。第一行 **2× 字**：天气名 + 气温（红，`℃`）+ 湿度（红黄棋盘抖）；第二行：实心纸飞机风向标（`wind360` / 中文风向，尖端指向风来向）+ 级数 + 空气质量（类别与 AQI）。地点名右上 2×。下方 6 小时柱为纯红。

#### 7D 柱色带

高低气温柱按 **10℃ 半开区间** `[lo, hi)` 填色（`app_weather.cpp`）。「相间」= 棋盘抖动混色。NOW 小时柱不用此表。

| 气温 ℃ | 填色 |
| --- | --- |
| ≥ 30 | 纯黄 |
| 20 – 30 | 红 / 白 相间 |
| 10 – 20 | 红 / 黄 相间 |
| 0 – 10 | 纯红 |
| −10 – 0 | 红 / 黑 相间 |
| −20 – −10（及更低） | 纯黑 |

柱下「周几」：周六、周日红色；周一至周五黑色。

### 6.4 相册

帧在 LittleFS；`vis.json` 控制是否参与翻页。「取消展示」只藏图，不关相册 App。

- **醒着**：定时翻页开且停留在相册 → 到期自动下一张  
- **关机**：前台相册且定时开 → RTC 定时深睡到点翻页再睡

## 7. 错误信息与错误日志

### 7.1 墨水屏

- 标题区短状态（如 `err`、`cfg`）  
- 正文 **「错误详情」** + 说明  
- 天气仍保留 NOW/7D 黄标，方便确认 BOOT 是否切过档  

「已经把错误画上屏」的路径一般**不再** LED 三短闪。硬失败（屏未就绪、网页起不来等）仍可能三短闪。

### 7.2 事件环

| 项 | 说明 |
| --- | --- |
| 存储 | LittleFS `/logs/errors.json` |
| 容量 | 最多 **40** 条 |
| 字段 | 时间、来源、正文（约 180 字） |
| 查看 | `/errors`；状态页有条数链接 |

未配置天气只提示步骤，**不**每按 BOOT 刷一条日志。

## 8. LED 语义（摘要）

完整说明在设备 Web `/help`。

| 图案 | 含义 |
| --- | --- |
| 按下常亮 | 任意键按住期间 |
| 上电三闪 | 已开机（本帧通常不刷屏） |
| 长按确认两闪 | UP 开 Web / DOWN 关机阈值到 |
| 慢闪 | 连 WiFi / 起 Web |
| 快闪 | HTTPS 拉数（待办 / 天气等） |
| 刷完一闪 | 全刷**完整成功**结束 |
| 三短闪 | 硬失败 |
| 熄灭 | 空闲 / 刷屏过程中 |

## 10. 主循环里一次「动作」的典型顺序

以天气上按 BOOT 为例：

```text
松手 → 等 ~500ms 连击窗
  → 推进 weather mode 并先 saveUiSession
  → WiFi（必要时）→ HTTPS GET Portal（长操作看门狗保护）
  → 解析 JSON → 画 framebuffer
  → 全刷（BUSY 等待；若中途按键 → 停刷 → 处理连按 → 刷新目标）
  → 完整成功：LED 短亮一闪；硬失败：三短闪
  → 短时忽略按键，防止连触
```

若灯快闪 3 下后屏完全不变：可能是拉数时看门狗/栈溢出复位（上电故意不刷屏）。**/错误** 可能留下「上次复位：看门狗 / Panic」。
