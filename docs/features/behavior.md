# 固件行为机制

> 说明 **Carte** 运行时怎么工作：上电、按键、多 App、Web 配置、联网拉数、错误记录。  
> 功能清单见 [固件功能说明](/features/)；本文偏「为什么按下去会这样」。  
> 版本：`{{DOC_VERSION}}`

---

## 1. 总体结构

固件是单线程 Arduino `setup` / `loop`，大致分层：

```text
按键 / 电源 / LED          ← app_power / app_led
        │
   main.cpp 路由            ← 决定：切 App / 刷屏 / 进 Web / 关机
        │
   ┌────┼────┬────┐
 App 绘制   Web 配置   错误日志
 (todo/…)  (app_web)  (app_errorlog)
        │
   WiFi / Portal / 天气代理
        │
   墨水屏 SSD2683 全刷
```

| 模块 | 职责 |
| --- | --- |
| `main.cpp` | App 会话、按键路由、进/出 Web、调用各 App 刷屏 |
| `app_power` | DOWN 长按关机、BOOT/DOWN 连击计数、空闲关机 |
| `app_config` | NVS 配置（WiFi、Portal、App 开关、天气位置…） |
| `app_web` | 设备端配置站（同 WiFi 站点或 AP 模式） |
| `app_*` | 各 App 拉数与画屏 |
| `app_errorlog` | 错误事件环，落盘 LittleFS，Web 可查 |

墨水屏**全刷约 10s+**。按键触发的刷屏期间主循环被占用，LED 用「呼吸」表示忙碌；刷完后灯灭。

## 2. 上电与关机

### 2.1 上电

1. 拉高 `PWR_HOLD` 保持供电  
2. 初始化 LED、电池脚、NVS、EPD、LittleFS 字库、错误日志、I2C / RTC  
3. 恢复上次 UI 会话（当前 App、天气模式、相册下标）；若该 App 已在设置里关闭，则落到**第一个仍启用的 App**  
4. **不自动刷屏**（保留墨水屏上一帧）  
5. LED **快闪 3 下**表示已开机  
6. 短时间忽略按键抖动  

### 2.2 关机 / 唤醒

| 操作 | 行为 |
| --- | --- |
| 长按 **DOWN ~3s** | 确认两闪 → 释放 `PWR_HOLD` → 深睡 |
| 深睡中按 **DOWN** | 唤醒开机（USB 仍供电时的「假关机」也能靠 DOWN 拉起来） |
| 空闲超时 | 可在 Web **设置**里配置无操作自动关机；**配置网页打开期间不计空闲** |

## 3. 按键模型

三键分工固定：

| 键 | 角色 |
| --- | --- |
| **UP / DOWN** | 切 App（短按）；UP 长按进 Web；DOWN 长按关机 |
| **BOOT** | **从不切 App**；只做「当前页内动作」，或在 Web 里退出配置 |

### 3.1 连击窗口

UP / DOWN / BOOT（非 Web）短按都走同一套：**松开后静默约 500ms**，把窗口内的点击数合并成一次「跳过 N 步」。

例：连按 DOWN 三次再停 → 一次前进 3 个 **已启用** App。

### 3.2 配置网页内外

| 场景 | BOOT | UP 短按 | UP 长按 | DOWN |
| --- | --- | --- | --- | --- |
| 普通 App | 页内功能（见下） | 上一个 App | 开 Web | 下一个 App / 长按关机 |
| Web 配置页 | **立刻退出 Web**，刷回当前可用 App | （忽略切换） | 再长按：AP → 同 WiFi 站点（或反过来） | （忽略切换） |

Web 里 BOOT **不等** 500ms 连击窗，松手后尽快 `webStop()` 并 `showCurrentApp`。

### 3.3 各 App 上 BOOT 做什么

| App | BOOT |
| --- | --- |
| 待办 | 重新拉 Portal 日记并全刷 |
| 日历 | 重绘（必要时校时） |
| 天气 | 切换模式 **NOW → 7D**，再拉对应接口并全刷；顶栏黄标指示当前档 |
| 相册 | 下一张（可展示列表内） |

天气切模式会先写入会话，再联网；避免拉数中途复位后「模式丢了像没按过」。

### 3.4 App 被关掉之后

Web **设置**可关闭部分 App（至少保留一个）。

- 上下键只在**启用**的 App 间循环  
- 只有 **1 个**启用时：**不画**顶栏 App indicator（没有切换意义）  
- 若进 Web 前停在 A，配置里把 A 关掉，再 BOOT 退出：会落到第一个仍启用的 App，**不会**把会话偷偷改回已禁用的 A

## 4. 多 App 与顶栏

启用掩码存在 NVS（`apps_enabled`）。顶栏从左到右是标题区，右侧是：

1. （可选）App indicator 色点  
2. 电池 / 充电图标  

成功状态一般不再写 `OK` 压在圆点上；失败时短状态字写在 indicator **左侧**。

## 5. Web 配置门户

长按 UP → 优先用已存 WiFi 开「同 WiFi 站点」；失败则开 AP 模式热点 `Note4C-Carte`。墨水屏显示对应图标与 URL；手机浏览器打开。

| 路径 | 作用 |
| --- | --- |
| `/` | 状态总览（含错误条数入口） |
| `/settings` | App 开关、空闲关机、日历/时间 |
| `/help` | 帮助（含 LED 图案说明；旧 `/led` 跳转至此） |
| `/wifi` | 最多 5 组 WiFi |
| `/auth` | Portal 地址、登录、Diary ID |
| `/todo` | 预览待办正文 |
| `/weather` | 天气开关 + 城市搜索选 LocationID |
| `/album` | 编辑 / 抖动 / 上传相册 |
| `/errors` | **错误事件记录**（见下） |

保存配置多为 HTTP 303 + 闪讯；**不会**自动退出 Web。退出靠 **BOOT**（或关机）。

Token：登录写入 NVS；若响应带 `X-Access-Token` 且剩余有效期短，会自动续写。

## 6. 联网与各 App 数据

### 6.1 待办

`GET {portal}/diary/detail?diaryId=`，正文里 `-` 未完成、`=` 已完成（未完成排前）。失败时墨水屏显示「错误详情」+ 原因，并记入错误日志。

### 6.2 日历

读 PCF8563；可联网 NTP（复位后校一次，平时按周期）。Web 可配周起始、时区、手动写 RTC。

### 6.3 天气

设备**不存**和风 Key。条件：天气启用 + 已登录 Token + 已选 LocationID + Portal Base URL。

经 Portal 代理：

| 模式 | 请求 |
| --- | --- |
| NOW | `/v7/weather/now` + `/v7/air/now` + `/v7/weather/24h`（实况 + 空气 + 前 6 小时柱） |
| 7D | `/v7/weather/7d`（高低气温柱） |

响应形态：`{ success, message, data }`，`data` 为和风 v7 结构（`code` / `now` / `hourly` / `daily`）。解析失败或业务失败时，屏上出错误详情，并写入错误日志。

### 6.4 相册

帧文件在 LittleFS；`vis.json` 控制是否参与翻页。「取消展示」只藏图，不关相册 App。

## 7. 错误信息与错误日志

### 7.1 墨水屏

拉取 / 配置类失败时：

- 标题区短状态（如 `err`、`cfg`）  
- 正文 **「错误详情」** + 完整说明（可换行）  
- 天气仍保留 header 上 NOW/7D 黄标，方便确认 BOOT 是否切过档  

「已经把错误画上屏」的路径，一般**不再**走 LED 三短闪，避免「灯闪了几下、屏没动」的错觉。硬失败（如屏未就绪、网页根本起不来）仍可能三短闪。

### 7.2 事件环（持久化）

模块：`app_errorlog`。

| 项 | 说明 |
| --- | --- |
| 存储 | LittleFS `/logs/errors.json` |
| 容量 | 环缓冲，最多 **40** 条 |
| 字段 | 时间（RTC/系统时间，否则开机相对时）、来源（`weather` / `todo` / …）、正文（截断约 180 字） |
| 写入时机 | 天气拉数失败、待办失败、日历读时失败、Web 启动失败等 |
| 查看 | 配置站 **`/errors`**；状态页也有条数链接 |
| 清空 | `/errors` 页「清空记录」 |

串口同时打 `[ErrLog] src: message`，方便 USB 调试时对照。

未配置天气（缺登录/城市）只提示配置步骤，**不**每按一次 BOOT 就刷一条日志，以免环被刷爆。

## 8. LED 语义（摘要）

完整动画说明在设备 Web `/help`。

| 图案 | 含义 |
| --- | --- |
| 按下常亮 | 任意键按住期间 |
| 上电三闪 | 已开机（本帧不刷屏） |
| 长按确认两闪 | UP 开 Web / DOWN 关机阈值到 |
| 慢闪 | 连 WiFi / 起 Web |
| 呼吸 | 正在全刷墨水屏 |
| 三短闪 | 硬失败 |
| 熄灭 | 空闲 |

## 9. 持久化一览

| 位置 | 内容 |
| --- | --- |
| NVS `carte` | WiFi、Portal、App 开关、天气位置、UI 会话（当前 App / 天气模式 / 相册下标）等 |
| LittleFS | 字库（HZK16 / ASC16 / uni2gb）、相册 `.2bp`、`vis.json`、**错误日志** |

首次刷固件后务必 `uploadfs`（或 `./flash.sh all`），否则中文与相册/错误落盘所在分区不可用。

## 10. 主循环里一次「动作」的典型顺序

以天气上按 BOOT 为例：

```text
松手 → 等 ~500ms 连击窗
  → LED 呼吸
  → 推进 weather mode 并先 saveUiSession
  → WiFi（必要时）→ HTTPS GET Portal（此段关闭 loop 看门狗，读流时仍喂灯）
  → 解析 JSON → 画屏（成功内容或「错误详情」）
  → 失败则 errorLog(...)
  → LED 灭（或硬失败三短闪）
  → 短时忽略按键，防止连触
```

若灯快闪 3 下后屏完全不变、错误页也是空的：多半是拉数时看门狗/栈溢出把板子复位了（上电故意不刷墨水屏）。新固件会在 **/错误** 里留下「上次复位：看门狗 / Panic」。

Web 退出类似，但 BOOT 立即处理，且会先纠正「当前 App 已被禁用」再刷屏。
